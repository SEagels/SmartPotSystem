# 五分钟答辩介绍稿

各位老师好，我是林禹行。我的毕业设计题目是《具有植株病害检测功能的智能花盆系统》。本课题面向家庭和办公场景中的盆栽养护问题，主要解决普通用户在养护过程中容易出现的浇水不及时、环境状态不可见、病害发现滞后以及远程管理不方便等问题。系统的总体设计思路可以概括为“环境感知、云端分析、移动交互、自动执行”，也就是通过硬件端采集植物环境和图像数据，通过云端进行存储、分析和病害检测，再通过 Web 端和 Android App 展示给用户，并支持远程补水、拍照和告警处理。

整个系统采用端、云、应用三层协同架构。端侧以 ESP32-S3 为核心控制器，连接 DHT11 温湿度传感器、BH1750 光照传感器、土壤湿度传感器、OV2640 摄像头和水泵模块。设备端主要完成环境数据采集、植物图像采集、自动补水执行、WiFi 联网和设备状态上报。云端后端基于 FastAPI 实现，负责用户认证、设备管理、遥测数据存储、自动补水判断、图片管理、病害检测、告警中心和养护建议生成。应用端包括 React Web 管理端和 Kotlin Android App，两端共用同一套后端 REST API，保证数据和业务逻辑一致。

在通信设计上，我采用了 MQTT、HTTP 和 WebSocket 组合的方式。MQTT 主要用于设备遥测数据上报、设备状态维护和云端控制命令下发，因为它轻量、实时性较好，适合物联网设备持续通信。图片数据体积较大，因此不通过 MQTT 传输，而是使用 HTTP multipart 上传到后端，便于文件存储和后续图像处理。Web 端则通过 WebSocket 接收后端推送的遥测更新、告警和命令状态变化，减少轮询，提高实时性。

在后端设计上，系统采用分层结构。API 层负责处理请求和响应，Service 层负责业务逻辑，Model 层负责数据库实体，Worker 层负责后台任务，例如遥测消费、图片检测、自动补水和定时拍照。数据库中主要包括用户、设备、遥测数据、图片、检测结果、告警、命令、补水事件和植物品种等核心表。用户登录后使用 JWT 进行认证，设备相关接口会校验设备是否属于当前用户，避免越权访问。

自动补水是本系统的一个核心闭环功能。系统为不同植物品种维护适宜的土壤湿度阈值，当设备上报的土壤湿度低于当前植物的阈值时，系统可以触发补水命令。设备端收到命令后控制水泵运行，并记录补水事件。同时，固件端也支持运行时配置同步，使云端修改植物品种阈值后，设备端能够使用新的补水策略。为了提升安全性，水泵控制中还加入了最大运行时长和冷却间隔，避免频繁补水或长时间运行。

病害检测是本课题区别于普通智能花盆的重要功能。系统采用端侧采图、云端推理的方式。ESP32-S3 只负责调用 OV2640 摄像头拍照并上传图片，不在设备端执行深度学习推理，这样可以降低硬件端算力压力。后端图片处理 Worker 会读取待检测图片，进行必要的图像质量评估和增强，然后调用 YOLOv11 ONNX 模型进行病害检测，输出病害类别、置信度和边界框。检测结果会写入数据库，并在置信度达到阈值时生成告警。前端和 App 可以查看原图、增强图、检测框、病害类别和处理建议。

在用户端方面，Web 管理端主要用于设备概览、设备详情、历史曲线、病害图片、告警中心和植物品种管理。设备详情页可以查看温湿度、土壤湿度、光照等传感器数据，也支持按日期查看历史曲线和一周趋势。Android App 面向日常移动使用，提供登录、设备列表、设备详情、告警中心和植物品种管理等功能，界面采用植物主题和毛玻璃风格，尽量贴合智能家居和盆栽养护场景。

在系统测试方面，我分别进行了硬件功能测试、通信测试、Web 和 Android 功能测试、病害检测测试以及系统联调测试。测试内容包括传感器采集、水泵控制、摄像头拍照、MQTT 通信、HTTP 图片上传、设备在线状态判断、历史曲线展示、告警展示和自动补水策略验证。联调过程中也发现并解决了一些问题，例如设备断电后仍显示在线的问题，后来通过 `last_seen_at` 心跳时效判断解决；植物阈值修改后设备端策略不一致的问题，则通过运行时配置下发机制解决。

整体来看，本系统完成了从环境采集、数据上传、云端分析、病害识别、告警展示到远程控制和自动补水的完整闭环。项目覆盖了嵌入式开发、物联网通信、后端服务、数据库设计、Web 前端、Android 移动端和图像识别等多个技术方向。当前系统仍有进一步优化空间，例如病害识别准确率依赖真实场景数据，后续可以采集更多 ESP32 摄像头实拍图片重新训练模型；硬件方面也可以增加水箱液位检测、BLE 配网和 OTA 升级等功能。以上就是我对本课题的整体介绍，请各位老师批评指正。
